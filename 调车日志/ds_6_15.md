## 一、LADRC 是什么？为什么用它替代 PID？

### PID 的致命弱点

传统 PID 有一个根本矛盾：

```
PID = Kp·e + Ki·∫e + Kd·de/dt

矛盾：
- 想要响应快 → 增大 Kp → 超调、振荡
- 想要无静差 → 增大 Ki → 积分饱和、相位滞后
- 想要抗扰动 → 只能靠反馈慢慢修正，扰动已经发生了才反应
```

PID 本质上是被动反应——"看到误差才修正"。对于智能车竞速这种场景（负载突变、电池电压下降、路面摩擦变化），PID 的响应总是慢半拍。

### LADRC 的核心思想

**LADRC = 线性自抗扰控制（Linear Active Disturbance Rejection Control）**，是韩京清教授提出的 ADRC 的工程化简化版。

核心思想一句话：**把所有不确定因素（外部扰动 + 模型误差）统一看作"总扰动"，用观测器实时估计出来，然后在前向通道中直接抵消掉。**

```
传统PID:  目标 → [PID] → [电机] → 速度 ──反馈──→ 误差计算
                           ↑
                      扰动直接作用于电机

LADRC:   目标 → [TD平滑] → [LSEF] → [b0补偿] → [电机] → 速度
                          ↑          ↑            ↑
                      [ESO观测器] → 估计扰动并前馈补偿

            ESO 在扰动影响输出之前就预估到了它！
```

## 二、本项目中的 LADRC 实现

### 三级流水线

代码在 `LADRC.cpp` 的 `update()` 中，每次调用依次执行三步：

```cpp
float LADRC::update(float expected_value, float measured_value) {
    trackingDifferentiator(expected_value);   // 1. TD
    extendedStateObserver(measured_value);    // 2. ESO
    linearFeedback();                         // 3. LSEF
    return u;  // 控制输出
}
```

### 第一级：TD（跟踪微分器）— 平滑目标输入

```cpp
// LADRC.cpp:116-136
v1 += v2 * h;                                    // v1 跟踪目标值
v2 += (-r²·(v1 - v0) - 2r·v2) * h;              // v2 是目标的微分(速度)
```

**作用**：把阶跃变化的期望速度 `v0` 变成平滑的过渡曲线 `v1`。避免了 PID 中"目标跳变 → 误差突变 → 输出冲击"的问题。

**物理直觉**：`r` 越大，跟踪越快。就像弹簧的刚度——刚度大就硬，响应快但可能抖；刚度小就软，平滑但滞后。

```
目标速度:  ▁▁▁▁████████████ (突变 0→2m/s)
TD输出v1:  ▁▁▁▁▂▃▅▆▇████████ (平滑过渡)
TD输出v2:  ▁▁▁▁▆▇█▅▃▁▁▁▁▁▁▁ (速度曲线，先加速后减速到0)
```

### 第二级：ESO（扩张状态观测器）— LADRC 的灵魂

本项目使用**一阶 ESO**（针对速度环）：

```cpp
// LADRC.cpp:170-192
// 一阶LESO: 两个状态就够了
// z1: 跟踪实际速度
// z2: 估计总扰动（包括摩擦、负载、参数不准等一切不确定因素）

float e = z1 - feedback_value;           // 观测误差
z1 += (z2 - 2*w0*e + b0*u) * h;        // 速度状态
z2 += (-w0²*e) * h;                     // 扰动状态 ← 关键！
```

**工作原理（物理直觉）**：

```
想象你在开车，踩一样的油门，但：
- 上坡时速度掉下来了 → 说明有"扰动"在减速
- 下坡时速度超了     → 说明有"扰动"在加速

ESO 就是通过对比"我给了多少u"和"实际速度是多少"，
反向推算出"现在有什么东西在干扰系统"。

它不需要知道具体是什么干扰（上坡、逆风、电池降压...），
统一算出"总扰动是多少 m/s²"，然后直接在控制输出中加回去。
```

### 第三级：LSEF（线性状态误差反馈）— 控制律

```cpp
// LADRC.cpp:227-249
float Kp = wc;                // 一阶: Kp = 控制器带宽
float e1 = v1 - z1;           // 误差 = 平滑目标 - 观测速度
float u0 = Kp * e1;           // 比例控制
u = (u0 - z2) / b0;           // 扰动补偿: 减去估计扰动 ← 关键！
```

**这里的妙处**：`z2` 是 ESO 估计的扰动。如果有个持续减速力（比如上坡），`z2` 会变成负值，`-z2` 就是正值（更多 PWM），**在误差变大之前就给了补偿**。这就是"主动抗扰"的含义。

```
                    u0 (比例控制，修正误差)
                    ↓
    u = (u0 - z2) / b0
              ↑
         z2 是估计的扰动（负值=阻力，正值=助力）
         -z2 就是提前补偿，不等误差变大
```

## 三、5 个参数的含义

```
参数    全称                 物理含义                         典型范围
──────────────────────────────────────────────────────────────────
 h      积分步长             离散化时间步长，= 控制周期(秒)    0.001~0.005
 r      跟踪速度因子         TD的响应速度，越大跟踪越快        20~200
 wc     控制器带宽           闭环响应带宽，越大控制越猛        1~50
 w0     观测器带宽           ESO观测带宽，越大估计越快         40~400
 b0     系统参数             控制量→加速度的增益系数           0.5~80
```

### `h` — 采样步长

本项目 LADRC 线程 1ms 周期 → h = 0.001。直接等于控制周期，不需要独立调。

### `r` — TD 跟踪速度

- **r 太小**：响应迟钝，加速无力。目标 2m/s → 实际要很久才跟上
- **r 太大**：目标跳变直接穿透，退化为无TD，输出冲击
- **经验**：r = 100~200 对于智能车足够了
- **当前默认**：r = 150

### `wc` — 控制器带宽（最需要调的参数）

调参的核心。一阶 LADRC 中 Kp = wc。

物理含义：闭环系统的响应截止频率。

| wc | 约等于响应时间 |
|----|-------------|
| 1  | ~0.16 秒 |
| 10 | ~0.016 秒 |
| 33 | ~0.005 秒 |

- **当前默认（配置文件）**：wc = 1（非常保守！）
- **预设1**：wc = 33（激进）

### `w0` — 观测器带宽（第二重要的参数）

ESO 的带宽。决定扰动估计的速度。

**黄金法则**：`w0 = 3~10 × wc`

- **w0 太小**：扰动估计滞后，z2 跟不上实际扰动
- **w0 太大**：对测量噪声敏感，z2 抖动大
- **经验公式**：w0 = 4 × wc
- **当前默认**：w0 = 120（来自配置文件）
- **预设1**：w0 = 133 ≈ 4×33 ✓

### `b0` — 系统参数

物理含义：1 单位控制输出产生多少加速度 (m/s² per PWM unit)。

- **b0 太小**：u = (u0-z2)/b0 → 控制输出被放大 → 可能振荡
- **b0 太大**：控制输出被缩小 → 响应迟钝

如何估计 b0：
```
给电机一个固定PWM (比如 300) → 测量稳态速度 v_ss
b0 ≈ v_ss / PWM  (粗略的稳态增益)
```

实际调的时候直接试：
- 振荡 → 增大 b0
- 太慢 → 减小 b0

- **当前默认**：b0 = 47（来自配置文件）
- **预设1**：b0 = 8

## 四、方向环 PD 与速度环 LADRC 的配合

### 完整控制链路

```
视觉循线                      方向环PD                      速度环LADRC
────────                     ─────────                     ─────────

imgproc.cpp                 my_global.cpp                 my_global.cpp
image_proc()   ──onto──→   pid_contol_handle()  ──onto_control──→  hight_frequence_...
   ↓                        (5ms, 优先级97)                      (1ms, 优先级99)
   ↓                                                               ↓
 计算出赛道                   onto_control =               target_speed_l = cruising_speed + onto_control
 方向偏移量                   pid_angle.compute             target_speed_r = cruising_speed - onto_control
 (角度误差)                   (onto, 0.0f)                              ↓
                                                          ladrc_left.calculatePWM(target_speed_l, left_speed)
                                                          ladrc_right.calculatePWM(target_speed_r, right_speed)
                                                                      ↓
                                                          motor_set_speed_ladrc(left_pwm, right_pwm)
```

### 逐层拆解

**第一层：视觉产出 `onto`**

`onto` 是图像处理算出的方向偏移量，正值=偏右需左转，负值=偏左需右转，幅度约 -30~+30。

**第二层：方向 PD 把 `onto` 变成 `onto_control`**

```cpp
// pid_contol_handle(), 5ms, 优先级97
onto_control = pid_angle.compute(onto, 0.0f);
//                              实际值  目标值(=0，表示期望走直线)
```

非线性 PD 内部（`my_pid.cpp:411-459`）：

```cpp
error = target - actual;           // = 0 - onto = -onto
error_delta = error - last_error;

output = error * Kp_segmented           // 线性P项（分段权重）
       + error * |error| * Kp2          // 非线性P²项（大误差时放大）
       + error_delta * Kd;              // D项（抑制振荡）
```

**为什么用非线性 PD？**

```
普通PD:  output = Kp * error + Kd * de/dt
          → 小误差和大误差的增益一样

非线性PD: output = Kp * error + Kp2 * error * |error| + Kd * de/dt
          → error=5:  5×Kp + 25×Kp2   (P²项贡献小)
          → error=20: 20×Kp + 400×Kp2  (P²项爆炸放大)

效果: 急弯(大误差)时暴力打舵，直道(小误差)时不敏感，刚好符合智能车需求
```

**第三层：LADRC 用差速实现转向**

```cpp
// hight_frequence_encoder_get_speed_handler(), 1ms, 优先级99
target_speed_l = cruising_speed + onto_control;  // 左轮 = 基准 + 修正
target_speed_r = cruising_speed - onto_control;  // 右轮 = 基准 - 修正

speed_to_pwm_l = ladrc_left.calculatePWM(target_speed_l, left_speed);
speed_to_pwm_r = ladrc_right.calculatePWM(target_speed_r, right_speed);
motor_set_speed_ladrc(speed_to_pwm_l, speed_to_pwm_r);
```

### 差速转向的数值实例（cruising_speed = 0.3 m/s）

| 场景 | onto | onto_control | 左轮目标 | 右轮目标 | 效果 |
|------|------|-------------|---------|---------|------|
| 直道 | 0 | 0 | 0.3 | 0.3 | 直行 |
| 微偏右 | +5 | -6 | -5.7 | 6.3 | 左转(右轮快) |
| 大弯偏右 | +25 | -35 | -34.7 | 35.3 | 急左转 |
| 微偏左 | -5 | +6 | 6.3 | -5.7 | 右转(左轮快) |

**关键**：左右轮速度之和 = `2 × cruising_speed = 0.6`（常量），转弯不改变总速度。差速量 = `2 × |onto_control|`。

### 时序配合

```
优先级99 (1ms):
  [LADRC][LADRC][LADRC][LADRC][LADRC][LADRC][LADRC][LADRC][LADRC][LADRC]
     ↑ 每次都读 onto_control，即使它5ms才更新一次也没关系

优先级97 (5ms):
  [方向PD]               [方向PD]               [方向PD]

优先级95 (10ms):
  [IMU+AHRS+按键]                         [IMU+AHRS+按键]

主循环 (不定周期):
  [图像处理→onto]   [图像处理→onto]   [图像处理→onto]
```

`onto_control` 是 `float`（32位原子写入），5ms 更新一次，LADRC 线程 1ms 读一次。读到旧值也没事——方向控制对延迟不敏感。

### 两个 PD 参数一览

| | 方向环 PD (pid_angle) | 速度环 LADRC (ladrc_left/right) |
|---|---|---|
| 输入 | onto (视觉方向偏移) | target_speed (目标速度) |
| 输出 | onto_control (差速量) | PWM (直接驱动电机) |
| 周期 | 5ms | 1ms |
| kp | 0.0（当前禁用） | — |
| kp2 | 0.65（非线性P²，主力） | — |
| kd | 4.0 | — |
| limit | 45.0 | — |
| h | — | 0.001 |
| r | — | 150 |
| wc | — | 1.0 |
| w0 | — | 120.0 |
| b0 | — | 47.0 |

**当前配置中 `kp=0`，完全靠 `kp2`（非线性P）和 `kd`（微分）工作**。这意味着直道上几乎不调方向（小误差时 kp2×error² 很小），弯道上才大力修正。

### 一句话总结配合关系

> **方向环 PD 决定"左右轮差多少"，速度环 LADRC 保证"左右轮各自精确执行那个差值"。** PD 算出差速指令，LADRC 抗住所有扰动（摩擦差异、电池降压、负载变化），确保两个轮子严格跟踪各自的目标速度。

## 五、调参实战指南

### 调参入口

**方式1：修改配置文件** (`/home/root/car_config.txt`)

```
whether_use_lardc: true
lardc_r: h=0.001f,r=150.0f,wc=1.0f,w0=120.0f,b0=47.0f,pwm_min=-1000.0f,pwm_max=1000.0f;
lardc_l: h=0.001f,r=150.0f,wc=1.0f,w0=120.0f,b0=47.0f,pwm_min=-1000.0f,pwm_max=1000.0f;
```

重启后生效。

**方式2：vofa+ 在线调参**（推荐，不用重启）

主循环的 TCP 客户端接收参数更新字符串。支持以下命令：

| 命令 | 作用 |
|------|------|
| `b0:47.0` | 左右轮 b0 一起改 |
| `wc:1.0` | 左右轮 wc 一起改 |
| `w0:120.0` | 左右轮 w0 一起改 |
| `r:150.0` | 左右轮 r 一起改 |
| `h:0.001` | 左右轮 h 一起改 |
| `kp:0.0` | 方向PD的Kp |
| `kp2:0.65` | 方向PD的非线性Kp2 |
| `kd:4.0` | 方向PD的Kd |
| `limit:45.0` | 方向PD输出限幅 |

通过 vofa+ 发送 `param_setting` 可以让新参数立即生效。

**方式3：READ/WRITE 命令持久化**

vofa+ 发 `WRITE` → 把当前参数写入 `car_config.txt`，发 `READ` → 从文件重载。用于保存调好的参数。

### 参数约束关系速查

```
硬约束:
  w0 > wc          (观测器必须比控制器快)
  w0 ≈ 3~10 × wc  (推荐比例)

软约束:
  wc ↑ → 响应快但容易振荡
  b0 ↓ → 控制输出放大
  r ↑  → TD更激进

相互抵消:
  wc↑  + b0↑  → 效果接近不变（都增强了控制力度）
  w0↑  + r↓   → 观测更准但TD更平滑

调参口诀:
  响应慢 → 先加 wc, 同步按比例加 w0
  振荡   → 先加 b0, 再降 wc
  起步慢 → 加 r
  速度不跟 → 加 wc, 减 b0
```

### 推荐调参流程

```
第1步：b0 初估计
  给电机固定 PWM=300，看稳态速度 v_ss。
  b0 ≈ v_ss / 300
  实际直接用默认 b0=47 开始即可

第2步：wc 粗调（核心）
  从保守开始: wc=1, w0=10 (保持 w0/wc=10)
  逐步增大 wc: 1→3→5→10→15→20
  观察编码器反馈速度是否紧跟目标:
    - 能跟上 → 继续加
    - 开始抖/有啸叫 → 回退一点

第3步：w0 精调
  固定 wc，调 w0:
    - 速度有静差 → 加大 w0 (观测器不够快，扰动没估计准)
    - 电机有高频噪音/啸叫 → 减小 w0
  保持 w0/wc = 4~6

第4步：r 微调
  看起步响应:
    - 起步太慢/无力 → 增大 r
    - 起步冲出去 → 减小 r

第5步：左右轮独立精调
  如果发现一侧轮子跟不上另一侧:
    - 在 car_config.txt 中分别调 lardc_l 和 lardc_r
    - 通常跟不上的那侧加 wc 或减 b0
```

### 典型参数配置参考

| 配置 | h | r | wc | w0 | b0 | 适用场景 |
|------|---|---|----|----|-----|---------|
| 保守 | 0.001 | 100 | 1 | 10 | 47 | 调试、初跑 |
| 当前默认 | 0.001 | 150 | 1 | 120 | 47 | 出厂配置 |
| 预设1 | 0.001 | 20 | 33 | 133 | 8 | 快速响应 |
| 激进 | 0.001 | 200 | 50 | 250 | 4 | 竞速极限 |

### 调参时的观察指标

在 vofa+ 上同时看这些信号可以快速定位问题：

| 现象 | vofa+ 信号 | 调参方向 |
|------|-----------|---------|
| 速度跟不上目标 | 实际速度 < 目标速度 | ↑wc 或 ↓b0 |
| 速度超调振荡 | 速度曲线在目标上下波动 | ↑b0 或 ↓wc |
| 稳态有偏差 | 速度稳定但差一点 | ↑w0 (ESO更准) |
| 电机啸叫 | PWM高频抖动 | ↓w0 (降观测噪声) |
| 起步冲车 | 初始PWM太大 | ↓r (TD更平滑) |
| 上坡掉速 | 速度在坡上明显下降 | ↑wc + ↑w0 (更强的抗扰) |
